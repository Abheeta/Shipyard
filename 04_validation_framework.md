# SHIPYARD — VALIDATION FRAMEWORK

## Strong signals

- Large volume of saved content.
- Recent concrete failure to retrieve/use it.
- Ugly workaround: screenshots, WhatsApp, Notes, folders, manual transcription.
- Weekly-or-more frequency.
- Meaningful time loss or decision fatigue.
- Already tried another solution.
- Already paid for an adjacent solution.
- Spontaneously asks when they can try the prototype.
- User describes the desired outcome without being prompted.

## Signals to kill/reframe

- People save content but rarely intend to use it.
- Current workflow already works.
- Perfect platform-native search would completely solve it.
- People like the concept but cannot recall a painful incident.
- Problem is infrequent.
- Users don't care enough to change behavior.
- Actual pain is different: choosing a workout, accountability, program design, etc.
- Competitors already solve the exact problem and users are satisfied.

## Potential wedges

1. Retrieval: semantic search across saved content.
2. Transformation: video/link → structured workout or recipe.
3. Decision: saved library → what should I do today?
4. Execution: structured workout → follow, timers, tracking.
5. Cross-platform capture: one share sheet from Instagram/TikTok/YouTube.
6. General information-to-action: saved content becomes a task, recipe, workout, place, product.
7. Geeky/B2B: messy sources → inconsistencies, missing pieces, or decisions requiring attention.
